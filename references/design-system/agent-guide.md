# Agent 使用说明（模板编排方法）

> 来源：小小东提示词归档的「提炼模板」资料包（基于公开区 689 条记录，2026-10-04）。本文保留原方法与规则，仅把“只写提示词、不生图”改为本项目的流程：**先给出至少四个机制不同的方向，用户选定后再展开提示词并调用生图工具**。验收规则不变：提示词检查只能确认描述合理，成图后才能判定通过。

## 在本项目中怎么用

1. `suggest_directions`：按主题与用途给出 ≥4 个机制各异的方向（模板 + 预设，必要时加一个 Mondo 设计师方向）。
2. 用户选择一个或几个方向（也可以说“你定”）。
3. `compose_prompt`：把变量展开成完整自然语言提示词。预设带 `structural_override` 时，按下文规则改写后，把改写结果作为 `raw_prompt` 提交。
4. `generate_image`：生成。成图后按 `acceptance_checks` 逐条检查，不通过就只改对应的那句话再生成。

---


模板在同目录 `templates.json`；人类可读的解释在 `template-library.md`；完整输入输出示例在 `examples.json` 与 `filled-examples.md`。在本项目中，这些模板由 `references/design-system/templates.json` 提供，工具层读取。

## 可复制的 Agent 指令

```text
你是视觉提示词编排 Agent。将用户需求转换成明确、可复用的图像提示词。
读取 templates.json，按用户用途选择一类模板和一个预设。

工作顺序：
1. 提取主体、用途、受众、比例、场景、准确文字、参考图用途、必要事实和禁止变化项。
2. 先满足用途，再满足风格。不允许只凭“高级感、清透、国风”等词选类。
3. 选择一个主模板和一个预设。模板不能混成大杂烩；应用 structural_override 时，删除被替换的基础句子，不能同时保留冲突结构。
4. 将主题映射为可见轮廓、动作或关系。每个象征必须解释它与主题的联系；最多一个主要象征和一次跨界动作。
5. 填充有意义的变量。没有文字就删除文字区；没有事实就省略对应信息；不能生成价格、统计、头衔、署名、天气、日期、引语归属等事实。
6. 参数化色彩角色和材质位置。不要把所有图都做成浅色纸纹；暗场保留明暗分区；摄影保留真实皮肤与自然细节；数据页优先读取。
7. 写出完整自然语言提示词，去掉占位符、元说明和重复形容词。明确要画什么、怎么摆、哪里有纹理、哪些文字准确出现。
8. 用风格锁检查文字与结构。若指定预设覆盖了某项锁，检查覆盖后的关系。发现冲突先改提示词再交付。
9. 返回选择理由、展开的参数、最终提示词、避免项、推荐比例、假设、待补信息、验收项与依据。用户只要提示词时，不调用生图工具；否则在方向确认后调用 `generate_image`。

必要提问：缺少主体、真实身份参考或必须准确呈现的关键信息时，只问会阻塞任务的问题，最多3个。低风险缺项用明确默认值并报告假设。
输出后不要声称模型效果已验证或原图可精确复现；只有真的调用了 `generate_image` 并看过成图，才可以说“已生成”。
```

## 输入结构

```json
{
  "task": "create_prompt",
  "topic": "核心主题",
  "deliverable": "海报",
  "audience": "受众",
  "subject": "可见主体",
  "scene": "环境",
  "action": "动作或关系",
  "headline": "准确标题，允许为空",
  "copy": ["准确短文案"],
  "facts": {},
  "references": [{"path": "参考文件", "role": "identity | product | style | layout"}],
  "ratio": "3:4",
  "template_id": null,
  "preset_id": null,
  "text_mode": "none | exact_short | typeset_later",
  "must_keep": [],
  "must_avoid": [],
  "target_syntax": "natural_language"
}
```

`identity` 参考只负责人物身份，`product` 参考负责真实包装结构，`style` 参考负责工艺，`layout` 参考负责位置关系。不能自动将一种参考的约束转移到另一种。没有参考时，不写“保持所提供人物”，也不保证真人身份一致。

## 输出结构

```json
{
  "template_id": "Txx",
  "preset_id": "Txx-1",
  "selection_reason": "用途与视觉机制为什么相符",
  "parameters": {},
  "prompt": "已展开、可直接提交的完整提示词",
  "avoid": "具体失败表现",
  "settings": {"ratio": "3:4", "target_syntax": "natural_language"},
  "assumptions": [],
  "missing_required": [],
  "acceptance_checks": ["可在成图中观察的条件"],
  "evidence_records": [1],
  "validation_status": "prompt_review_only"
}
```

这是工作约定，字段值范围由上面的枚举约束；不是工具原生 API。缺少必需信息时，`prompt` 留空，`missing_required` 写明缺项。

## 路由顺序

| 用户需要 | 优先模板 | 判断依据 |
|---|---|---|
| 真人身份、自然皮肤与动作 | T09 / T10 / T11 | 棚拍、环境、婚礼分别处理；不加海报纸纹 |
| 完整数据、课程或嘉宾 | T20 / T22 / T23 | 人物名录、汇报、解释性信息的阅读结构 |
| 包装与产品识别 | T12 / T13 / T14 / T15 | 食品、液体、植物手绘、科技空间分别处理 |
| 材料与空间表达 | T05 / T17 / T18 / T19 | 地貌材料、工程关系、框景入口、近摄暗腔 |
| 情绪或文化主视觉 | T01 / T02 / T03 / T04 / T06 / T07 / T08 | 按尺度、跨界、负空间、工艺关系选择 |
| 创意尺度与探索 | T16 | 巨物是否真正成为可参与的空间 |
| 社媒集合或日历 | T21 / T24 | 九格互补或日期—照片—寄语结构 |

应用场景不独占模板。咖啡既可用 T12 做产品近摄，也可用 T06 做市集招贴；先看用途，再看品类。信息多的技术发布优先 T22/T23，只有少量主题字的科技海报才优先 T15。

## 文字策略

- `none`：删除标题、说明、日期、标志和页脚，只保留视觉关系；禁止自动补英文。
- `exact_short`：把允许出现的文字列成完整白名单。除白名单外不出现文字；图像结构允许遮挡时，也不得遮挡必读字形。
- `typeset_later`：生成不带文字的底图，并列出文字区位置、层级和留白需求；之后用排版工具加入准确文字和图表。字墙类模板需要在后续排版中实现字墙，不可因无字底图就宣称风格锁已满足。

信息图里的内容先整理为命题与证据，复杂页面拆张。无来源的二维码、徽标、条码不能用随机图案冒充可用功能。

## 系列化变体

同一系列锁定模板、字体层级、色彩角色、纹理位置与跨界动作；变化景别、叙事焦点、主题色相和模块跨度。每次只改一至两个可控维度，保留至少两个明确的核心关系。

提出三个方向时，分别给出不同主机制的完整方案，不把三类关键词拼在同一张图里。不同预设有结构替换时必须分别展开，不能简单改名字。

## 风格与成图检查

1. 第一眼焦点是否符合模板：字墙、光隙、暗腔、真实人物、产品或数据？
2. 原本要保留的大小关系、图地关系和遮挡方向是否还成立？
3. 材质是否仅出现在对应载体，光线是否一致？
4. 必须读取的文字、身份与数值是否准确？
5. 是否出现输入以外的对象、信息、标志或符号？

提示词检查只能确认描述是否合理。实际生图后才可判定成图通过；失败时指出具体不满足的关系，修改该关系对应的句子，避免叠加“更高级、更精致”修饰词。

## 示例调用

```text
为“一个月的咖啡店活动海报”生图：先区分产品促销、咖啡市集、门店纪念三种用途；每种各选一个主模板，填好变量并输出完整自然语言提示词与验收条件，确认后生成。
文字仅允许使用我提供的标题、日期与价格，不得补造。
```
